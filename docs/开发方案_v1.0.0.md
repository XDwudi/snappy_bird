## 1. 项目概述

### 1.1 一句话定位

> 一款融合 Flappy Bird 操控手感与 Vampire Survivors 式 roguelike 成长的小程序生存游戏 —— 单指操作，越玩越强，每局都不一样。

### 1.2 核心体验

| 维度 | 设计目标 |
|------|----------|
| 操作 | 单指点击，0学习成本，3秒上手 |
| 单局时长 | 3~10分钟，适配碎片化场景 |
| 成长感 | 每局内获得10~20次升级选择，构筑流派 |
| 重玩性 | 能力随机组合 + 难度递增，每局体验不同 |
| 社交 | 好友排行榜 + 分享，轻社交驱动回流 |

### 1.3 核心循环

```
点击飞行 → 躲避障碍 → 收集经验 → 升级选能力 → 变强生存 → 死亡重开
    ↑                                                        |
    └────────────────────────────────────────────────────────┘
```

## 2. 核心玩法设计

### 2.1 基础飞行机制

沿用 Flappy Bird 经典手感，确保直觉操作：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 重力加速度 | 0.45 px/frame² | 每帧持续下落加速 |
| 点击上升力 | -8.0 px/frame | 单次点击施加的瞬间向上速度 |
| 最大下落速度 | 12 px/frame | 防止下落过快不可控 |
| 前进速度（世界滚动） | 3.0 px/frame | 障碍物向左移动速度，随时间增速 |
| 小鸟水平位置 | 固定在屏幕 1/3 处 | 小鸟X轴不动，世界左移产生前进感 |

**手感微调原则**：重力与上升力需反复调参，目标手感为「轻点即升，松手即落」，上升响应延迟≤1帧。

### 2.2 障碍物系统

#### 2.2.1 基础障碍 — 管道

- 上下成对的管道，中间留有间隙供小鸟通过
- 管道从屏幕右侧生成，匀速左移至屏幕外销毁
- 每通过一对管道得 1 分 + 生成经验球

| 难度阶段 | 间隙宽度 | 管道间距 | 滚动速度 | 持续时间 |
|----------|----------|----------|----------|----------|
| 新手期 | 220px | 320px | 3.0 px/f | 0~30s |
| 普通期 | 180px | 280px | 3.5 px/f | 30s~90s |
| 挑战期 | 150px | 240px | 4.0 px/f | 90s~180s |
| 极限期 | 130px | 220px | 4.5 px/f | 180s+ |

#### 2.2.2 进阶障碍类型（渐进引入）

| 类型 | 出现阶段 | 行为描述 | 设计意图 |
|------|----------|----------|----------|
| 标准管道 | 第0秒 | 固定位置，上下成对 | 基础难度 |
| 移动管道 | 第60秒 | 上下缓慢浮动 | 增加预判难度 |
| 旋转管道 | 第120秒 | 围绕中心点摆动 | 动态间隙变化 |
| 尖刺障碍 | 第150秒 | 顶/底部长出尖刺，间歇出现 | 限制安全区域 |
| 追踪导弹 | 第180秒 | 从右侧飞来，缓慢追踪小鸟Y轴 | 持续压力源 |

> **MVP 范围**：仅实现标准管道 + 移动管道。其余类型在上线版本迭代加入。

### 2.3 碰撞判定

- **小鸟碰撞箱**：略小于视觉尺寸（视觉尺寸的 70%），提升手感容错
- **碰撞对象**：管道、地面、天花板、障碍物
- **碰撞结果**：立即死亡（除非拥有护盾/无敌能力）
- **擦边奖励**：小鸟穿越间隙时，若距管道边缘<15px，触发"擦边"特效 + 额外经验奖励

### 2.4 经验与升级

```
通过管道/拾取经验球 → 经验条增长 → 经验条满 → 触发升级 → 暂停游戏弹出选择面板
```

| 要素 | 说明 |
|------|------|
| 经验来源 | 通过管道(+5)、拾取经验球(+10)、擦边奖励(+15) |
| 经验球 | 沿管道间隙路径生成，金色光点，自动吸引范围 60px |
| 升级阈值 | 每级所需经验递增：Lv1→2 需20，此后每级 +15 |
| 选择面板 | 暂停游戏，展示3张能力卡牌，玩家选1张后继续 |

## 3. Roguelike系统设计

### 3.1 设计理念

借鉴 Vampire Survivors 的核心乐趣 —— **每局构筑不同流派**：

- 每局从零开始，无跨局养成（保证公平性）
- 单局内获得 10~20 次升级机会
- 能力可叠加升级（同能力多次选择会增强）
- 能力之间存在隐性协同，玩家自主发现流派

### 3.2 能力体系

能力分为三大类：**被动强化**、**主动技能**、**特殊机制**。

#### 3.2.1 被动强化类（基础属性提升）

| 能力名 | 图标 | 效果 | 最大等级 | 每级增量 |
|--------|------|------|----------|----------|
| 轻羽 | 🪶 | 降低重力 8% | Lv3 | 8%/级 |
| 顺风 | 🌬️ | 提升上升力 10% | Lv3 | 10%/级 |
| 灵巧 | ✨ | 缩小碰撞箱 12% | Lv3 | 12%/级 |
| 磁吸 | 🧲 | 经验球吸引范围 +50px | Lv3 | 50px/级 |
| 贪婪 | 💰 | 经验获取 +25% | Lv3 | 25%/级 |
| 坚韧 | ❤️ | 获得1层护盾，被击破后30s恢复 | Lv2 | +1层/级 |

#### 3.2.2 主动技能类（自动/条件触发）

| 能力名 | 图标 | 效果 | 最大等级 | 每级增量 |
|--------|------|------|----------|----------|
| 时间扭曲 | ⏳ | 受击前0.3s自动减速50%，持续1s，CD 20s | Lv3 | CD -3s/级 |
| 瞬移闪避 | 💫 | 即将碰撞时自动瞬移至间隙中心，CD 30s | Lv2 | CD -5s/级 |
| 护盾爆发 | 🛡️ | 每25s自动获得1层护盾 | Lv3 | CD -3s/级 |
| 凤凰之翼 | 🔥 | 死亡时原地复活1次，保留所有能力 | Lv1 | 一次性 |

#### 3.2.3 特殊机制类（改变规则）

| 能力名 | 图标 | 效果 | 最大等级 | 每级增量 |
|--------|------|------|----------|----------|
| 慢速世界 | 🐌 | 全局障碍物速度 -10% | Lv3 | 10%/级 |
| 双倍积分 | 📊 | 通过管道得分 ×2 | Lv3 | +1倍/级 |
| 幸运光环 | 🍀 | 升级时能力选项 +1（3→4选1） | Lv2 | +1选项/级 |
| 连击之心 | ⚡ | 连续通过5管道不被击中，获得5s无敌 | Lv2 | 减少2管道/级 |
| 缩小射线 | 📐 | 障碍物间隙 +15px | Lv3 | 15px/级 |

#### 3.2.4 能力协同示例（隐性流派）

| 流派名称 | 核心能力组合 | 效果 |
|----------|-------------|------|
| 闪避流 | 灵巧 + 慢速世界 + 缩小射线 | 碰撞箱极小 + 间隙极大 + 速度慢，几乎无敌 |
| 经济流 | 贪婪 + 磁吸 + 双倍积分 | 经验获取拉满，升级飞快 |
| 护盾流 | 坚韧 + 护盾爆发 + 凤凰之翼 | 多层保险，容错极高 |
| 擦边流 | 连击之心 + 时间扭曲 + 瞬移闪避 | 主动贴边获取奖励，自动保命 |

> 流派不做显式引导，由玩家在反复游玩中自主发现，增强探索乐趣。

### 3.3 升级选择面板交互

```
┌─────────────────────────────────┐
│          ⬆️ 升级！ Lv.5           │
│      选择一项能力强化            │
├──────────┬──────────┬──────────┤
│  🪶 轻羽  │  🧲 磁吸  │ 🛡️ 护盾  │
│  Lv2→3   │  Lv1→2   │  Lv1→2  │
│ 降低重力  │ 吸引范围  │ 自动护盾 │
│  -8%     │ +50px    │ CD 25s  │
└──────────┴──────────┴──────────┘
```

- 游戏暂停，背景半透明遮罩
- 3张卡牌从底部弹出，附带轻微弹性动画
- 点击卡牌 → 确认选择 → 面板收起 → 游戏继续
- 已满级能力不再出现在选项中
- 若所有能力均满级，升级改为"全属性 +5%"

### 3.4 能力随机规则

- 初始可选能力池：全部能力 Lv0 状态
- 每次升级随机抽3个（未满级的能力）
- 抽取权重：未拥有能力(权重3) > 已拥有可升级(权重2)，鼓励尝试新能力
- 拥有"幸运光环"后，抽取数量 +1

## 5. 技术方案

### 5.1 技术栈选型

| 选项 | 方案 | 优势 | 劣势 | 结论 |
|------|------|------|------|------|
| **A** | 微信原生 + Canvas 2D | 包体最小、完全可控、无引擎开销 | 需手写渲染/碰撞/动画 | ✅ **MVP首选** |
| B | Cocos Creator | 可视化编辑器、内置物理引擎、动画系统 | 引擎包体~2MB、学习成本、构建流程复杂 | 后续迭代考虑 |
| C | LayaAir | 性能好、3D支持 | 社区较小、文档不如Cocos | 不推荐 |

**决策：MVP 采用方案 A（微信原生 + Canvas 2D）**

理由：
1. Flappy Bird 类游戏逻辑简单，Canvas 2D 完全胜任
2. 包体可控，主包可压缩至 2~3MB，远低于 10MB 限制
3. 无引擎依赖，首屏加载快，性能可控
4. 后续如需复杂动画/特效，可评估迁移至 Cocos Creator

### 5.2 性能设计

| 指标 | 目标 | 策略 |
|------|------|------|
| 帧率 | ≥30fps（目标60fps） | requestAnimationFrame 驱动、对象池复用、减少GC |
| 主包体积 | ≤3MB | 素材压缩、按需加载、无重型依赖 |
| 首屏加载 | ≤2s | 精简首屏资源、loading并行预载 |
| 内存占用 | <100MB | 对象池、及时销毁离屏对象、避免闭包泄漏 |

**关键优化手段**：
- **对象池**：管道、经验球、特效粒子均使用对象池，避免频繁创建/销毁
- **离屏 Canvas**：静态背景预渲染到离屏 Canvas，每帧仅 drawImage
- **脏区域优化**：仅重绘变化区域（MVP阶段可视帧率情况决定是否启用）
- **setData 最小化**：游戏内数据通过 Canvas 渲染，不经过 WXML setData

### 5.3 渲染架构

```
┌─────────────────────────────────────┐
│           主 Canvas (游戏层)          │
│  ┌─────────────────────────────────┐│
│  │  背景层 (天空/云/远景) - 慢速滚动 ││
│  ├─────────────────────────────────┤│
│  │  障碍层 (管道/尖刺) - 正速滚动    ││
│  ├─────────────────────────────────┤│
│  │  实体层 (经验球/道具)             ││
│  ├─────────────────────────────────┤│
│  │  小鸟层 (玩家)                    ││
│  ├─────────────────────────────────┤│
│  │  特效层 (粒子/擦边/升级光效)      ││
│  ├─────────────────────────────────┤│
│  │  UI层 (分数/经验条/能力图标)      ││
│  └─────────────────────────────────┘│
└─────────────────────────────────────┘
```

所有层共用一个 Canvas，通过绘制顺序实现层次。背景使用视差滚动（远景慢、近景快）增强纵深。

### 5.4 微信小游戏 vs 微信小程序

| 维度 | 微信小游戏 | 微信小程序 |
|------|-----------|-----------|
| 渲染 | Canvas/WebGL 全屏 | WXML + Canvas |
| 适合 | 纯游戏 | 应用+游戏 |
| API | wx.createCanvas 等 | Page/Component + Canvas |

**决策：采用微信小程序框架（非小游戏）**

理由：
1. 非游戏界面（主界面、排行榜、设置）可用 WXML 开发，开发效率高
2. 游戏部分用全屏 Canvas 覆盖
3. 小程序与小游戏共享大部分 API（登录、分享、广告）
4. 项目规范明确要求"微信原生小程序框架"

## 8. 数值体系框架

### 8.1 难度曲线

```
难度
 ↑
 │                    ╱ ← 极限期(180s+): 速度4.5, 间隙130
 │                 ╱
 │              ╱ ← 挑战期(90~180s): 速度4.0, 间隙150
 │           ╱
 │        ╱ ← 普通期(30~90s): 速度3.5, 间隙180
 │     ╱
 │  ╱ ← 新手期(0~30s): 速度3.0, 间隙220
 └────────────────────────────→ 时间(s)
```

### 8.2 经验与升级数值

| 等级 | 累计经验 | 单级经验增量 | 说明 |
|------|----------|-------------|------|
| 1→2 | 20 | 20 | 首次升级快速触发 |
| 2→3 | 45 | 25 | |
| 3→4 | 75 | 30 | |
| 4→5 | 110 | 35 | |
| 5→6 | 150 | 40 | |
| 6→7 | 195 | 45 | |
| ... | ... | +15/级 | 线性增长 |
| 15→16 | 600 | 95 | 后期升级放慢 |

> 经验来源：通过管道 +5、拾取经验球 +10、擦边 +15。一局3分钟约通过30~40管道 + 拾取15~20经验球，可获得12~16次升级。

### 8.3 能力数值总表（详见策划文档）

能力数值配置采用独立 JS 配置文件（`game/config/AbilityConfig.js`），结构化定义每个能力的等级数值，便于策划调整。

### 8.4 分数计算

| 行为 | 基础分 | 加成分 | 说明 |
|------|--------|--------|------|
| 通过管道 | +1 | ×双倍积分倍率 | 主要分数来源 |
| 擦边通过 | +3 | - | 高风险高回报 |
| 拾取经验球 | +2 | - | 附带经验值 |
| 存活时间 | +1/5s | - | 鼓励生存 |

## 9. 商业化与社交设计

### 9.1 MVP阶段（不接入）

MVP 版本不接入任何商业化组件，专注核心玩法验证。

### 9.2 上线版本规划

| 模块 | 方案 | 合规要点 |
|------|------|----------|
| 激励视频复活 | 死亡后看广告复活1次/局 | 非强制，明确告知 |
| 插屏广告 | 返回主界面时展示 | 频率控制，非弹窗骚扰 |
| 好友排行榜 | 微信开放数据域 | 仅展示好友关系链 |
| 分享功能 | 分享当前得分截图 | 不可强制，不可必得奖励 |
| 角色皮肤 | 金币购买/解锁 | 纯外观，无属性加成 |

> 所有商业化设计严格遵守微信平台规范，禁止诱导分享/关注，支付/广告需用户主动触发。

## 10. 开发里程碑

### MVP 阶段（3个三日迭代）

#### 迭代1：核心飞行 + 障碍

| 天 | 任务 | 负责角色 | 交付物 |
|----|------|----------|--------|
| D1 | 项目搭建 + 飞行物理 + 基础渲染 | 前端 | 可运行的小鸟飞行Demo |
| D2 | 管道生成 + 碰撞检测 + 死亡逻辑 | 前端 | 完整Flappy Bird玩法 |
| D3 | 测试验收 + 手感调优 | 测试/策划 | 验收报告 + 参数调整建议 |

**迭代1验收标准**：小鸟可飞行、管道正常生成、碰撞死亡正常、手感可接受。

#### 迭代2：经验系统 + 能力系统

| 天 | 任务 | 负责角色 | 交付物 |
|----|------|----------|--------|
| D4 | 经验球 + 经验条 + 升级触发 | 前端 | 经验系统可用 |
| D5 | 能力注册框架 + 5个基础能力实现 + 升级面板 | 前端 | 可选择能力并生效 |
| D6 | 测试 + 能力数值平衡初调 | 测试/策划 | Bug清单 + 数值调整 |

**迭代2验收标准**：经验系统完整、升级面板可交互、至少5个能力可正常选择并生效。

#### 迭代3：UI完善 + 难度曲线 + 收尾

| 天 | 任务 | 负责角色 | 交付物 |
|----|------|----------|--------|
| D7 | 主界面 + 结算页 + HUD + 音效接入 | 前端/美术 | 完整UI界面 |
| D8 | 难度递增系统 + 剩余能力实现 + 全量联调 | 前端 | 全功能可玩版本 |
| D9 | 全量测试 + Bug修复 + 验收交付 | 测试/前端 | 验收报告 + 可交付版本 |

**迭代3验收标准**：满足MVP全部验收标准，可交付测试。

### 上线版本阶段（后续规划）

- 社交功能：好友排行榜、分享
- 商业化：激励视频复活、插屏广告
- 内容扩展：更多障碍类型、更多能力、皮肤系统
- 性能优化：帧率/包体/内存全面优化

## 11. 风险评估与应对

| 风险 | 等级 | 影响 | 应对措施 |
|------|------|------|----------|
| Canvas性能不足 | 中 | 帧率掉帧 | 对象池 + 离屏渲染 + 减少绘制调用 |
| 手感不佳 | 高 | 核心体验差 | 迭代1专注调参，策划反复测试验证 |
| 能力平衡性差 | 中 | 玩法无深度 | 数值表独立配置，快速迭代调整 |
| 包体超限 | 低 | 审核风险 | 像素素材压缩，音频低码率，持续监控 |
| 微信审核驳回 | 中 | 上线延迟 | 严格合规自查，MVP不接商业化降低风险 |
