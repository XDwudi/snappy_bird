## A. 框架正确性与可拓展性

### A1. 状态机/主循环/渲染管线
1. 无 delta time，全计时硬绑 60fps（GameConfig.js:5；Game.js:291 frameCount 驱动一切）。低端机掉帧时游戏整体变慢但难度不变——结构性风险，已记 DECISIONS D2。
2. rAF 降级路径静默终止：Game.js:269-273 若两种 rAF 均不存在则不再自调度，无 setTimeout 兜底、无日志。
3. UPGRADING 期间浮动文字/擦边特效继续衰减（Game.js:297-298 在状态检查之前），但天气 elapsed 暂停——冰雹悬空定格，语义可接受、视觉略怪；且选牌回来时 "+EXP" 提示已消失，节奏断。
4. 凤凰动画期间 update() 完全冻结（301-304），画面定格 1.5s，设计如此。
5. `_buildGameCtx()` 每帧调用两次（326 update / 1124 render），render 侧输出字段无意义，白建对象+3 个闭包（532-548）。
6. 雨停后重力瞬时归 0：rainResidual.dry() 不回写 gravityModifier（RainEffect.js:120-133），Game.js:322 每帧清零——与方案 7.2.2"积水未干逐渐变重"不符。

### A2. 扩展成本实测
- 新增纯数值被动能力：改 2 处（AbilityConfig + AbilitySystem.getStats），成本低。但 effectText 与实现分离，靠人工对齐（已现偏差案例）。
- 新增主动技能：改 4-5 处，CD 逻辑手写散布（reset/tickCooldowns/CD 计算/触发），无注册式 CD 框架。
- 新增环境效果：≥5 处，其中 WeatherSystem.js:148-149 与 Game.js:1416-1417 两处硬编码 names/colors 映射未走注册表，漏改显示 `?`。
- 新增障碍物：Obstacle 基类设计良好，但 Game.js 生成/更新/渲染硬编码 `this.pipes`（357-406, 1114），新类型需改 Game.js ≥4 处。

### A4. 内存与性能
- ObjectPool 零引用。每帧分配热点：`_buildGameCtx`×2、冰雹 trail 每帧 push（Hailstone.js:28-29，峰值每秒 ~6000 小对象）、雨/风粒子。冰雹+雨叠加是首个掉帧压力点。
- floatingTexts 无封顶但 50 帧自灭，可控；hailstones 由生成间隔+离屏回收自然封顶 ~100 颗，可控。
- 各循环 splice 倒序删除写法正确。

## C. 游戏体验与正反馈

### C1. 难度曲线
- 单次拍翅上升 ≈71px，垂直余量 ~163px ≈ 2.3 次拍翅行程，比原版宽松 40%，新手友好 ✅。
- 60s 时速度 3.0→4.5、间隙 180→140 已全部拉满（RAMP 均 3600 帧=60s），**第 2 分钟起难度停滞**——与 3~10 分钟单局目标矛盾，是 C 面最重要结构问题。天气是唯一长局压力源但爬坡周期（10 分钟）远长于典型单局。

### C2. 反馈节奏
| 事件 | 时间点 |
|---|---|
| 第一次升级 | ~3-4s ✅ |
| 第一个道具 | ~6-8s ✅ |
| 第 2~4 次升级 | ~15-35s ✅ |
| 首次天气 | 期望 ~50-70s ⚠️ 偏晚 |
| 难度拉满 | 60s ⚠️ 之后停滞 |

前期正反馈密度优秀；30s~90s 是"升级变稀+天气未到+难度已满"的体验低谷。建议天气 START_TIME 降至 15-20s 并保底一次教学性质的风。

### C3. 死亡与复活
- HP=2 + 1s 无敌，惩罚柔和 ✅；复活重置屏幕中央 + 2s 无敌，不会复活即死 ✅。
- 爽感缺口：凤凰为史诗稀有度（权重 1.5），前几级几乎抽不到，复活动画曝光率极低，投入产出比差。

### C4. "不好玩/不爽"清单（8 条）
1. 水平风形同虚设 → 系数 0.3 提至 1.5~2.0 或改水平漂移
2. 二段跳 2~8 帧窗口反人类 → 放宽到 3~18 帧（150~300ms）
3. 雨甩水无教学 → 首次下雨浮动文字提示
4. 风暴之子/狂暴重力增益 → 重力排除出 totalMul
5. 60s 后难度停滞 → 增加第二段缓坡至 180s
6. 无敌期小鸟消失 → 改半透明
7. 天气太晚+史诗难抽 → START_TIME 提前 + 新手池加权
8. 护盾不掉连击 → 护盾消耗也 resetCombo，或明写为设计特性
